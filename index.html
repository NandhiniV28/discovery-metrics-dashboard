Details
Methodology: TDIs = Jira project TDI, issue type Feature, Zone = Communications Services, with an assignee and a target quarter (Fix Version) both set — this matches the GitHub release dashboard's count exactly (52 vs. this dashboard's earlier unfiltered 67) and is applied consistently across every metric here. Discovery allocation = sum of "Allocation in Days" on child Epics (any project) whose title contains "discovery" and whose parent is the TDI, excluding epics from the Design team's project (DES). A TDI that transitioned "In Discovery → Ready to Plan" without ever having a linked discovery epic is not counted in the trend chart, allocation chart, or 3S breakdown table below — only TDIs with at least one discovery epic represent tracked discovery work. The first three tiles bucket the current 3S cycle's completed TDIs by their total discovery allocation (1–5 / 6–10 / >10 days) — all of a TDI's discovery epics are grouped into one entry and summed, so a TDI counts once even with multiple epics; TDIs with no allocation set aren't counted in any bucket. The fourth tile, Discovery Epics In Progress, is independent of that: it counts TDIs whose discovery epic(s) have a Jira Sprint overlapping the current 3S window and aren't Done/Closed yet, regardless of whether the TDI has already moved to Ready to Plan — so a TDI can appear in both a completed bucket and this tile if it has more than one discovery epic. "Refresh from Jira" requires running the local server (python3 server.py) in this folder — opened as a plain file, the button will tell you so instead of silently failing.
