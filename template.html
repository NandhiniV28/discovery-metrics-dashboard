Details
Methodology: TDIs = Jira project TDI, issue type Feature, Zone = Communications Services, with an assignee and a target quarter (Fix Version) both set — this matches the GitHub release dashboard's count exactly (52 vs. this dashboard's earlier unfiltered 67) and is applied consistently across every metric here. Discovery allocation = sum of "Allocation in Days" on child Epics (any project) whose title contains "discovery" and whose parent is the TDI, excluding epics from the Design team's project (DES). The trend chart, allocation chart, and 3S breakdown table below count every TDI that moved Backlog or In Discovery → Ready to Plan, whether or not it has a linked discovery epic — a TDI with no discovery epic simply shows 0 allocation rather than being excluded. The first three tiles bucket the current 3S cycle's discovery work by total allocation (1–5 / 6–10 / >10 days) — both TDIs that already completed discovery this cycle and ones still ongoing/not yet started (for visibility into estimates vs. actual pace, not just finished work); all of a TDI's discovery epics are grouped into one entry and summed, so a TDI counts once even with multiple epics, and TDIs with no allocation set aren't counted in any bucket. The fourth tile, Discovery Epics In Progress, is the same "still open" set on its own: TDIs whose discovery epic(s) have a Jira Sprint overlapping the current 3S window and aren't Done/Closed yet, regardless of whether the TDI has already moved to Ready to Plan. "Refresh from Jira" requires running the local server (python3 server.py) in this folder — opened as a plain file, the button will tell you so instead of silently failing.
